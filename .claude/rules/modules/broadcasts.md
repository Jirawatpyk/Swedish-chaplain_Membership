# Broadcasts / E-Blast (F7 `010-email-broadcast` + `014-email-broadcast-advance`, F119)

- **Stack added**: 4 aggregates (Broadcast / BroadcastDelivery / MarketingUnsubscribe / RecipientSegment) · Tiptap@3.22.5 + isomorphic-dompurify@2.36.0 (both exact-pin) + email-validator@^2 + @tanstack/react-virtual@^3.
- **SDK**: `resend` exact-pinned at **6.35.0** (spec 141). Its `audiences.*` is an alias of `segments.*`, so those calls (and `contacts.list({ audienceId })`) go to `/segments…` — MEASURED 2026-10-30 to be the same resource as `/audiences` (same ids, same contacts, delete on one is gone on the other). Every SDK call is pinned on the wire in `tests/contract/resend/`. `RESEND_DEBUG` logs request paths, which carry emails — production refuses `RESEND_DEBUG=true` at boot (`src/lib/env.ts`); `RESEND_BASE_URL` would redirect the Bearer key — every `new Resend(…)` passes `baseUrl: RESEND_API_BASE_URL` (`src/lib/resend-api-base-url.ts`), and a new client must too. 6.35 passes a non-JSON error page's HTTP status through; the gateway reads every SDK status via `httpStatusOf`, which keeps the 4.8 reading (the SDK's own `application_error` = a transient 500), so an edge's HTML 404 never means "already gone" — read SDK errors only through it, and raw-fetch responses only through its twin `rawHttpStatusOf`. A falsy `audienceId` turns `contacts.remove` into an account-wide `DELETE /contacts/{email}`, so every gateway method taking an id or an email runs `assertNonEmpty` first, and `removeContactFromAudience` also refuses a segment id that is not UUID-shaped (`invalid_identifier`, spec 140 DT4; case-insensitive, no trim). It sends the email as given (no encoding): lowercase, because every push lowercases (spec 140 s3 R1-A) and the erasure capture is lowercase, and Resend matches contacts case-sensitively (MEASURED 5 Nov 2026). It refuses an address containing `/ ? # % \` before any request (`invalid_identifier`, R1-K). Resend answers 200 for a contact not in the segment, so `detached` can include one already absent. Two addresses that collide once lowercased are refused by the completion rule on the import leg only (Resend's count differs from the resolved count); the legacy leg dedupes at resolve.
- **Every gateway call is bounded (spec 140 s2a)**: `boundedCall` gives each REQUEST ONE `AbortSignal.timeout(callTimeoutMs)` (default `RESEND_CALL_TIMEOUT_MS` = 10 s, in the port) across all its attempts, so a port call that loops (`addContactsToAudience`, `listAudiences`) runs N × C (`listAudiences({ deadlineAt })` also stops paging once less than one call fits and answers `truncated`, spec 140 DT5; its only caller, reclaim, shares that deadline with its delete chunks and counts the rest as `deferredDeletes`); a new SDK call must pass `{ signal }`, a raw `fetch` must take the same signal, and a new create must be `retry: 'rate_limit'` (it retries only a 429, which created nothing; a retried create that reached Resend mints a second resource). The one exception is `legacyResendBroadcastsGateway` (`createBroadcastRetry: 'retryable'`), wired only by `makeDispatchScheduledBroadcastDeps` and deleted with the legacy leg in slice 4. `createContactImport` has its own budget, `IMPORT_CALL_TIMEOUT_MS` (30 s, ASSUMED). `createResendBroadcastsGateway({ callTimeoutMs, importCallTimeoutMs })` builds a 50 ms gateway for tests; `AbortSignal.timeout` runs on real timers, so fake timers cannot drive it. The legacy dispatch leg skips a row holding import columns (DL7).
- **Resend error classes (spec 140 s3, DT3)**: `classifyResendError` keys on status, then `name`: a 409 `resource_locked` is `retryable` with subKind `locked` (retried inside one call under `retry: 'retryable'`, never by a create's `'rate_limit'`); a 429 `daily_quota_exceeded` / `monthly_quota_exceeded` is `permanent` (code = the name, metric `resend_429` on both legs); a 429 `rate_limit_exceeded` or with no / an unknown name stays `retryable`; any other 409 stays `idempotency_conflict`. The raw `*Once` readers keep 409 → `other`. A new subKind added to the port's `GatewayRetryableSubKind` fails to compile until it is listed in `GATEWAY_RETRYABLE_SUB_KINDS` (`_classify-thrown.ts`); it must also go in the tick's metric maps and `dispatchBudgetExhausted`, or it lands in `unclassified`. Every probe result is read through `probedStatusOf`; a status reader tests positively (name what continues, refuse the rest). **Resend matches contacts case-sensitively** (MEASURED 2026-11-05) and answers 200 `deleted: true` to any segment-contact DELETE, so a 200 proves nothing: every address pushed to Resend must be lowercase (both push paths, `createContactImport` and `addContactsToAudience`, send `toLowerCase()` of each address), because the erasure detach sends lowercase.
- **The import leg works a row under a dispatch lease (spec 140 s2b, migration 0322)**: `buildAudienceTick` claims `dispatch_lease_token` + `dispatch_lease_expires_at` in its step-1 lock tx for `LEASE_TTL_MS`, checks it (`checkDispatchLease`, `SELECT … FOR UPDATE`) before every irreversible Resend call with `CALL_HEADROOM_MS` (`IMPORT_HEADROOM_MS` before `createContactImport`), and releases it in a `finally`; all bounds live in `application/use-cases/_dispatch-lease.ts`, pinned by `dispatch-lease-budget.test.ts`. **Every row writer takes a REQUIRED `lease: LeaseToken | null`** (`applyTransition` + nine more; all ten are pinned in `broadcast-lease-sql-shape.test.ts`): the holder passes its token (a lost one reports its own signal — `lease_lost` throw, `null`, `false`, or 0 rows), everyone else passes `null`, and a `null` STATUS change clears the lease. A new writer on this table takes the same parameter or the SQL-shape gate goes red. A new irreversible Resend call on the import leg needs a `leaseGate` before it — except the reclaim of an id this tick just minted (A2) and of the audience it just created when its attach loses the lease (`audience_leaked` if that delete is undecided). A `null` same-status re-time (`scheduledFor` set) is REFUSED while a live lease is held: confirm-schedule asks `hasLiveDispatchLease` first under its row lock (409 `dispatch_in_progress`, before any write), and the repo backstop throws a `BroadcastConcurrentMutationError` with `observedStatus: LEASE_HELD` (no clock read; drift reports the probed status). A tick that skips a row another tick holds reports `LEASE_HELD_BY_ANOTHER_TICK`, a different value and never clears the lease; the completion stamp is fenced `token OR status IN SENDING_STARTED_BROADCAST_STATUSES`; a lost lease after `/send` is not critical while `rowStatus` is `sending` (INFO) / `approved` (WARN, unexpected) (else critical: `sent_but_transition_lost`, or `completion_stamp_failed` at the stamp); a restart stopped by a lease check — or a release CAS whose token was cleared (`ReleaseOutcome`, the release CASes probe the token on a miss) — answers `lease_lost`, by any other CAS miss `cas_lost` → `unknown_or_already_processed` (one `restartStopAnswer`), and only a tick that answers the hold records it and resets the retry clock; a failed audience attach is read back before its audience is kept or deleted, and a DB fault there answers `dispatch.server_error` (phase `attach_audience`); a lease running short on its own holder is the `lease_expiring` kind (WARN, own bucket), and a lease stop inside a restart (the hold, the self-heal) passes through as `lease_expiring` / `lease_lost`; the pre-call check and the release each wait at most `CHECK_LOCK_TIMEOUT_MS`. The due scan excludes a live lease on every flag state, the legacy leg skips one (cell 23), and no IMPORT row starts after `ROW_START_CUTOFF_MS` (DL9; the legacy leg has no cutoff); `makeBuildAudienceTickDeps` takes the route's `tickBudget` as a required parameter.
- **Orphaned Resend ids (spec 140 s2c, migration 0325)**: an id our side created and then left on no live `broadcasts` row goes to `broadcast_orphaned_resend_ids` through `recordOrphanBestEffort` (own tx; a failed insert is the critical `orphan_record_failed` line; log the reason as `orphanReason`, never `reason`, which is redacted), written at the CALLER that holds the id and the requester, never inside a shared gateway helper. Its port is `BroadcastOrphansRepo` (one per table, tenant-bound). Settlers: the `cleanup-audiences` drain and the erasure cascade, both through `_settle-orphan-at-resend.ts`, and both skip an id a NON-TERMINAL row holds (type-matched: `broadcast` ↔ `resend_broadcast_id`, `audience` ↔ `resend_audience_id`). A new path that drops a Resend id from a row, or fails to attach one, records it here or says in its docblock why not. The import leg's `failTerminally` deletes the row's draft first (re-read, `leaseGate`, `deleteDraftBeforeStandingRefusal`; a handed draft catches the row up through `catchUpHanded`); a caller that already deleted it passes `draftSettled: true`. Every undecided settle calls `markOrphanAttempted` (lists read `ORDER BY attempts, created_at`), a settle counts only when its CAS won, an audience whose terminal holder changed within `AUDIENCE_CLEANUP_GRACE_MS` is still held, and in erasure pass (b) a tenant audience orphan at `ORPHAN_STUCK_ATTEMPTS` (8) is reported, not withheld (review round 1). The migration's `chamber_app` UPDATE is column-level (`settled_at`, `outcome`, `attempts`, `last_attempted_at`).
- **The Resend Broadcasts surface is separate from F1/F4 transactional** — its own API key, suppression list, webhook endpoint and reputation pool; the webhook is pinned to the Node runtime for Svix HMAC raw-body verification. Env `RESEND_BROADCASTS_API_KEY` + `RESEND_BROADCASTS_WEBHOOK_SECRET` + `UNSUBSCRIBE_TOKEN_SECRET` (≥32 bytes, distinct from `AUTH_COOKIE_SIGNING_SECRET`) + `BROADCASTS_FROM_EMAIL` + `FEATURE_F7_BROADCASTS`. Resend's `Idempotency-Key` is inert on `POST /broadcasts`.
- **Content rules**: sanitiser allowlist (FR-002a) is `p`/`br`/`strong`/`em`/`u`/`a[href]`/`ul`/`ol`/`li`/`h1-h4`/`blockquote`/`hr`, schemes `http`/`https`/`mailto`, **no `<img>`** (F119 images go through the separate image allowlist); subject ≤200, body ≤200 KB; applied in Application and the raw body is never persisted.
- **State rules**: quota reserves at `submitted` and consumes at `sending→sent`, with `currentQuotaYear` in the tenant's TZ. Immutable after submit (DB trigger `broadcasts_immutable_after_submit_fn`; several migrations redefine it, so read the newest `CREATE OR REPLACE` in `drizzle/migrations/` — the state-machine ELSE is fail-closed). F119's approval round (`FEATURE_EBLAST_MEMBER_APPROVAL`) is documented in `docs/runbooks/eblast-approval.md`.
- **Audience ceiling**: 500 recipients per tick (`DELIVERABLE_RECIPIENTS_PER_TICK`) unless `FEATURE_F7_IMPORT_AUDIENCE` is ON; the Resend account is on the Free plan (1,000 contacts, 3 segments), so at most two broadcasts can be in flight.
- **Resend provider facts, MEASURED 2026-10-29** (live Broadcasts account, sink address only; see spec 138):
  - DELETE on a `queued` or `sent` broadcast → 403 ("Only draft or scheduled broadcasts can be deleted"); the send still completes. `sending` is inferred from the message, not caught.
  - **DELETE of an audience while its broadcast is `queued` makes the broadcast `failed`, and no mail goes out.** Never delete an audience another tick could be sending into; the row CAS fence (D-037) exists for this.
  - A second `/send` on any non-draft broadcast → 422 ("Only draft broadcasts can be sent or scheduled"), whatever the `Idempotency-Key`. So no double send, but `classifyResendError` reads 422 as `permanent`: probe before you believe it (`_probe-refused-send.ts`).
  - Against a deleted audience, `POST /broadcasts` → 404 "Audience not found" and `POST /contacts/imports` → 404 "Segment not found", while GET of its old import still says `completed`.
  - `failed` and `scheduled` are real broadcast statuses; `normaliseStatus` reads both as `unknown`, so they are refused fail-closed. A `cancelled` inherited id is dead on the import leg (only a draft can be sent) and is re-minted.
  - **MEASURED 2026-10-30** (sink only, 2 runs): `POST /broadcasts/{id}/cancel` on a `queued` broadcast → GET answers **`canceled` (one L)**, as Resend's docs spell it, at +0/2/15/45 s; DELETE on it → 403 ("Only draft or scheduled broadcasts can be deleted"); GET after that → 200 (it still exists); a re-send → 422. `normaliseStatus` maps both `canceled` and `cancelled` to our `cancelled` (PR #698) — before that all three `cancelled` arms were dead (the erasure cascade's 403 + cancelled, the gate's 403 on a cancelled id, the import leg's re-mint).
  - **MEASURED 2026-11-03** (the maintainer's `/verify` of spec 140 s2c, sink account holding only the `General` segment): a DELETED audience answers `GET /audiences/{id}` → 404 but `DELETE` → **403 `validation_error` "Cannot delete last audience."** (Resend checks "last audience" before it checks the id). So `deleteAudience` probes a 403, and only a 403, with ONE `audiences.get` on the same signal (inside the call's `RESEND_CALL_TIMEOUT_MS`): 404 / 410 → already gone (`resend.broadcasts.audience_already_absent`, `via: 'probe_after_403'`); found, 5xx or a throw → the DELETE's own `permanent` classification. Pinned in `tests/contract/resend/broadcasts-sdk.contract.test.ts`.

An exception to a closed finding greps every syntactic form of the old claim in the same commit (spec 140 s2a retro, 2026-11-01).
