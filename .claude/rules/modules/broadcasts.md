# Broadcasts / E-Blast (F7 `010-email-broadcast` + `014-email-broadcast-advance`, F119)

- **Stack added**: 4 aggregates (Broadcast / BroadcastDelivery / MarketingUnsubscribe / RecipientSegment) · Tiptap@3.22.5 + isomorphic-dompurify@2.36.0 (both exact-pin) + email-validator@^2 + @tanstack/react-virtual@^3.
- **SDK**: `resend` exact-pinned at **6.35.0** (spec 141). Its `audiences.*` is an alias of `segments.*`, so those calls (and `contacts.list({ audienceId })`) go to `/segments…` — MEASURED 2026-10-30 to be the same resource as `/audiences` (same ids, same contacts, delete on one is gone on the other). Every SDK call is pinned on the wire in `tests/contract/resend/`. `RESEND_DEBUG` logs request paths, which carry emails — production refuses `RESEND_DEBUG=true` at boot (`src/lib/env.ts`); `RESEND_BASE_URL` would redirect the Bearer key — every `new Resend(…)` passes `baseUrl: RESEND_API_BASE_URL` (`src/lib/resend-api-base-url.ts`), and a new client must too. 6.35 passes a non-JSON error page's HTTP status through; the gateway reads every SDK status via `httpStatusOf`, which keeps the 4.8 reading (the SDK's own `application_error` = a transient 500), so an edge's HTML 404 never means "already gone" — read SDK errors only through it, and raw-fetch responses only through its twin `rawHttpStatusOf`. A falsy `audienceId` turns `contacts.remove` into an account-wide `DELETE /contacts/{email}`, so every gateway method taking an id or an email runs `assertNonEmpty` first.
- **Every gateway call is bounded (spec 140 s2a)**: `boundedCall` gives each REQUEST ONE `AbortSignal.timeout(callTimeoutMs)` (default `RESEND_CALL_TIMEOUT_MS` = 10 s, in the port) across all its attempts, so a port call that loops (`addContactsToAudience`, `listAudiences`) runs N × C; a new SDK call must pass `{ signal }`, a raw `fetch` must take the same signal, and a new create must be `retry: 'rate_limit'` (it retries only a 429, which created nothing; a retried create that reached Resend mints a second resource). The one exception is `legacyResendBroadcastsGateway` (`createBroadcastRetry: 'retryable'`), wired only by `makeDispatchScheduledBroadcastDeps` and deleted with the legacy leg in slice 4. `createContactImport` has its own budget, `IMPORT_CALL_TIMEOUT_MS` (30 s, ASSUMED). `createResendBroadcastsGateway({ callTimeoutMs, importCallTimeoutMs })` builds a 50 ms gateway for tests; `AbortSignal.timeout` runs on real timers, so fake timers cannot drive it. The legacy dispatch leg skips a row holding import columns (DL7).
- **The import leg works a row under a dispatch lease (spec 140 s2b, migration 0322)**: `buildAudienceTick` claims `dispatch_lease_token` + `dispatch_lease_expires_at` in its step-1 lock tx for `LEASE_TTL_MS`, checks it (`checkDispatchLease`, `SELECT … FOR UPDATE`) before every irreversible Resend call with `CALL_HEADROOM_MS` (`IMPORT_HEADROOM_MS` before `createContactImport`), and releases it in a `finally`; all bounds live in `application/use-cases/_dispatch-lease.ts`, pinned by `dispatch-lease-budget.test.ts`. **Every row writer takes a REQUIRED `lease: LeaseToken | null`** (`applyTransition` + nine more; all ten are pinned in `broadcast-lease-sql-shape.test.ts`): the holder passes its token (a lost one reports its own signal — `lease_lost` throw, `null`, `false`, or 0 rows), everyone else passes `null`, and a `null` STATUS change clears the lease. A new writer on this table takes the same parameter or the SQL-shape gate goes red. A new irreversible Resend call on the import leg needs a `leaseGate` before it — except the reclaim of an id this tick just minted (A2) and of the audience it just created when its attach loses the lease (`audience_leaked` if that delete is undecided). A `null` same-status re-time (`scheduledFor` set) is REFUSED while a live lease is held: confirm-schedule asks `hasLiveDispatchLease` first under its row lock (409 `dispatch_in_progress`, before any write), and the repo backstop throws a `BroadcastConcurrentMutationError` with `observedStatus: LEASE_HELD` (no clock read; drift reports the probed status). A tick that skips a row another tick holds reports `LEASE_HELD_BY_ANOTHER_TICK`, a different value and never clears the lease; the completion stamp is fenced `token OR status IN SENDING_STARTED_BROADCAST_STATUSES`; a lost lease after `/send` is not critical while `rowStatus` is `sending` (INFO) / `approved` (WARN, unexpected) (else critical: `sent_but_transition_lost`, or `completion_stamp_failed` at the stamp); a restart stopped by a lease check — or a release CAS whose token was cleared (`ReleaseOutcome`, the release CASes probe the token on a miss) — answers `lease_lost`, by any other CAS miss `cas_lost` → `unknown_or_already_processed` (one `restartStopAnswer`), and only a tick that answers the hold records it and resets the retry clock; a failed audience attach is read back before its audience is kept or deleted, and a DB fault there answers `dispatch.server_error` (phase `attach_audience`); a lease running short on its own holder is the `lease_expiring` kind (WARN, own bucket), and a lease stop inside a restart (the hold, the self-heal) passes through as `lease_expiring` / `lease_lost`; the pre-call check and the release each wait at most `CHECK_LOCK_TIMEOUT_MS`. The due scan excludes a live lease on every flag state, the legacy leg skips one (cell 23), and no IMPORT row starts after `ROW_START_CUTOFF_MS` (DL9; the legacy leg has no cutoff); `makeBuildAudienceTickDeps` takes the route's `tickBudget` as a required parameter.
- **The Resend Broadcasts surface is separate from F1/F4 transactional** — its own API key, suppression list, webhook endpoint and reputation pool; the webhook is pinned to the Node runtime for Svix HMAC raw-body verification. Env `RESEND_BROADCASTS_API_KEY` + `RESEND_BROADCASTS_WEBHOOK_SECRET` + `UNSUBSCRIBE_TOKEN_SECRET` (≥32 bytes, distinct from `AUTH_COOKIE_SIGNING_SECRET`) + `BROADCASTS_FROM_EMAIL` + `FEATURE_F7_BROADCASTS`. Resend's `Idempotency-Key` is inert on `POST /broadcasts`.
- **Content rules**: sanitiser allowlist (FR-002a) is `p`/`br`/`strong`/`em`/`u`/`a[href]`/`ul`/`ol`/`li`/`h1-h4`/`blockquote`/`hr`, schemes `http`/`https`/`mailto`, **no `<img>`** (F119 images go through the separate image allowlist); subject ≤200, body ≤200 KB; applied in Application and the raw body is never persisted.
- **State rules**: quota reserves at `submitted` and consumes at `sending→sent`, with `currentQuotaYear` in the tenant's TZ. Immutable after submit (DB trigger `broadcasts_immutable_after_submit_fn`; several migrations redefine it, so read the newest `CREATE OR REPLACE` in `drizzle/migrations/` — the state-machine ELSE is fail-closed). F119's approval round (`FEATURE_EBLAST_MEMBER_APPROVAL`) is documented in `docs/runbooks/eblast-approval.md`.
- **Audience ceiling**: 500 recipients per tick (`DELIVERABLE_RECIPIENTS_PER_TICK`) unless `FEATURE_F7_IMPORT_AUDIENCE` is ON; the Resend account is on the Free plan (1,000 contacts, 3 segments), so at most two broadcasts can be in flight.
- **Resend provider facts, MEASURED 2026-10-29** (live Broadcasts account, sink address only; see spec 138):
  - DELETE on a `queued` or `sent` broadcast → 403 ("Only draft or scheduled broadcasts can be deleted"); the send still completes. `sending` is inferred from the message, not caught.
  - **DELETE of an audience while its broadcast is `queued` makes the broadcast `failed`, and no mail goes out.** Never delete an audience another tick could be sending into; the row CAS fence (D-037) exists for this.
  - A second `/send` on any non-draft broadcast → 422 ("Only draft broadcasts can be sent or scheduled"), whatever the `Idempotency-Key`. So no double send, but `classifyResendError` reads 422 as `permanent`: probe before you believe it (`_probe-refused-send.ts`).
  - Against a deleted audience, `POST /broadcasts` → 404 "Audience not found" and `POST /contacts/imports` → 404 "Segment not found", while GET of its old import still says `completed`.
  - `failed` and `scheduled` are real broadcast statuses; `normaliseStatus` reads both as `unknown`, so they are refused fail-closed. A `cancelled` inherited id is dead on the import leg (only a draft can be sent) and is re-minted.
  - **MEASURED 2026-10-30** (sink only, 2 runs): `POST /broadcasts/{id}/cancel` on a `queued` broadcast → GET answers **`canceled` (one L)**, as Resend's docs spell it, at +0/2/15/45 s; DELETE on it → 403 ("Only draft or scheduled broadcasts can be deleted"); GET after that → 200 (it still exists); a re-send → 422. `normaliseStatus` maps both `canceled` and `cancelled` to our `cancelled` (PR #698) — before that all three `cancelled` arms were dead (the erasure cascade's 403 + cancelled, the gate's 403 on a cancelled id, the import leg's re-mint).
- **Provider enums are measured, not assumed.** Every Resend value the code matches on (broadcast and import statuses, error codes, limits) is MEASURED with a date, or cites the Resend doc URL. The cost of not doing so: the code matched `cancelled` while Resend answers `canceled`, so three decision arms never fired (measured 2026-10-30; retro #701). Known open instances, all for spec 140's status table: the import poll's `canceled` (not a documented import status, `build-audience-tick.ts`); `normaliseStatus`'s `sending` (neither documented nor measured) and its two-L `cancelled` alias (not observed: Q1 measured `canceled` on the cancel-a-queued-broadcast path only, and no Resend doc lists `cancelled`; keep it until 140 measures or cites otherwise). The current provider facts are in `specs/139-eblast-erasure-close/research.md`.
- **A bound in prose names its source.** A number or limit written into the RoPA, a runbook or a port docstring (attempt counts, budgets, which row states can exist) names the constant or constraint it comes from (`RETRY_BACKOFF_MS`, `RESEND_CALL_TIMEOUT_MS`, `IMPORT_CALL_TIMEOUT_MS`, a CHECK's name), so a reviewer checks it against one line. An exception to a closed finding greps every syntactic form of the old claim in the same commit (spec 140 s2a retro, 2026-11-01).
- **A new writer names its neighbours.** A reviewer-asked mechanism that changes when a row column is written (a lease, a clock, an id) lists, in its plan row and before GREEN, every existing writer of that column and what each now answers (spec 140 s2b retro, 2026-11-03).
