## The one all six found

`resend-broadcasts-gateway.ts:447` — `complete: result.data?.has_more !== true`, under a docblock
promising *"a missing field reads as 'not complete' … an absent signal must not be reported as a
verified-complete count"* and an inline comment contradicting **itself** in one sentence.
`undefined !== true` is `true`. Six independent reports on one line; the mapping had **no test at
any layer**, because all nine doubles inject `complete` on the Application port, so nothing could
observe `has_more` at all.

Fixed to `=== false` and pinned per case by the first wire-level test this mapping has ever had
(`tests/unit/broadcasts/infrastructure/resend-audience-contact-count.test.ts`).

**That test then found two things no reviewer did.**

1. **`result.data?.data.length` guarded only the OUTER level.** A payload-less 200 threw a
   `TypeError`, and `withRetry` short-circuits only a `GatewayThrowable` — so a programming bug
   was retried 1/2/4/8/16 s and rethrown as `retryable`/`timeout`: laundered into a transport
   fault at 31 s per call. Two of five cases timed out at 30 s, which is how it surfaced. Now
   `result.data?.data?.length`.

2. **MEASURED, and it corrects my own alarm.** I read `resend@4.8.0`'s
   `ErrorResponse { message, name }`, saw no `statusCode`, and concluded that
   `classifyResendError`'s `err?.statusCode ?? 500` made every 404 a retryable 5xx — which would
   have killed the `already_absent` arm of the GDPR detach in production. **Wrong.** A read-only
   probe returns `{"statusCode":404,"message":"Audience not found","name":"not_found"}` — the SDK
   passes the parsed body through, so the field reaches runtime even though the type omits it.
   The existing `{statusCode: 404}` stubs are faithful to the wire. I inferred from a type
   instead of measuring, and the advisor accepted the inference too.

   What the probe *did* establish: **`GET /audiences/{id}/contacts` on a nonexistent audience
   answers `200 {"object":"list","has_more":false,"data":[]}`.** So `getAudienceContactCount` can
   never return `not_found`, and a DELETED audience arrives as `count: 0` with `complete: true` —
   the one shape that makes the count authoritative. On the live leg that filed *"expected 150,
   actual 0"* into an append-only table and paged § 22.3, reading as "nobody received the mail".
   Closed by a zero clause in `usable`, mutation-proven.
