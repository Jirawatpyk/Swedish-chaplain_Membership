# ขั้นตอนทดสอบใช้งานจริง (UAT) — การอนุมัติ E-Blast สองฝ่าย ของ SweCham (ภาษาไทย)

**ฟีเจอร์**: F119 การอนุมัติ E-Blast สองฝ่าย (FR-035, US7, SC-005) ฉบับภาษาอังกฤษอยู่ที่
`uat-walkthrough-en.md` ทั้งสองฉบับมีเนื้อหาตรงกัน หากแก้ไขฉบับหนึ่ง ต้องแก้อีกฉบับด้วย
**อ้างอิงโค้ด ณ**: branch `119-eblast-approval-workflow` คอมมิต `328c4029f` รวมการแก้ไขเวลาส่งที่เสนอ (FR-016) (24 ก.ย. 2569)
**ผู้ทดสอบ**: เจ้าหน้าที่ SweCham อย่างน้อยสองคน — คนหนึ่งรับบท **สมาชิก** อีกคนรับบท
**ฝ่ายการตลาด** — และมีผู้ดูแลระบบ (maintainer) คอยเปิด-ปิดสวิตช์ให้

เป้าหมายคือพา E-Blast ทดสอบหนึ่งฉบับผ่านทุกขั้นตอน ได้แก่ **ส่งเรื่อง → จัดรูปแบบ → สมาชิกขอแก้ไข
→ จัดรูปแบบใหม่ → สมาชิกอนุมัติ → ยืนยันเวลาส่ง → ส่งจริง** และตรวจให้แน่ใจว่า **ไม่มีอีเมลฉบับใด
หลุดไปถึงผู้ที่ไม่อยู่ในรายชื่อเจ้าหน้าที่ที่กำหนดไว้** จากนั้นชุดทดสอบ B จะไล่ทดสอบขั้นตอนที่เส้นทางหลัก
ไม่ได้ผ่าน เพื่อให้ได้เห็นครบทุกสถานะอย่างน้อยหนึ่งครั้ง (US7-AS2)

## 1. สิ่งที่ต้องเตรียมให้พร้อมก่อนเริ่ม

ต้องครบทั้ง 10 ข้อก่อนเริ่มขั้นที่ 1 รายการนี้ตรงกับ `quickstart.md` หัวข้อ 4

| ข้อ | สิ่งที่ต้องเตรียม | เหตุผล |
|---|---|---|
| P1 | มี **บริษัทสมาชิกสำหรับทดสอบ** ในระบบจริง (เช่น "SweCham Internal Test") และ **สถานะสมาชิกปกติ ไม่ขาดอายุ** | สมาชิกที่ขาดอายุยังเปิดดูและตัดสินใจเรื่อง E-Blast ของตัวเองได้ แต่ส่ง E-Blast ใหม่ไม่ได้ |
| P2 | **เพิ่มอีเมลของเจ้าหน้าที่ทุกคนที่ร่วมทดสอบเป็นผู้ติดต่อ (contact) ของบริษัทสมาชิกนี้** และเปิดรับอีเมลการตลาด | รายชื่อผู้รับแบบกำหนดเองรับเฉพาะอีเมลที่เป็นผู้ติดต่อในระบบเท่านั้น **ถ้าไม่ทำข้อนี้ ระบบจะปฏิเสธรายชื่อ และการทดสอบจะติดตั้งแต่ขั้นส่งเรื่อง — เป็นสาเหตุที่พบบ่อยที่สุดในวันแรก** |
| P3 | บริษัทสมาชิกทดสอบมี **บัญชีเข้าพอร์ทัลที่ใช้งานอยู่** โดยใช้อีเมลที่ **ยังไม่เคยเป็นบัญชีเจ้าหน้าที่** (อีเมลหนึ่งมีได้เพียงบัญชีเดียว) เช่น อีเมลแฝง (alias) ที่ผู้ร่วมทดสอบคนหนึ่งเปิดอ่านได้ อีเมลนี้ต้องเป็นผู้ติดต่อของบริษัทด้วย (P2) และต้องอยู่ในรายชื่อผู้รับ (P5) | ถ้าไม่มีบัญชีพอร์ทัลที่ใช้งานอยู่ ปุ่ม "ส่งให้สมาชิก" จะถูกปฏิเสธ ("บริษัทสมาชิกยังไม่มีผู้ใช้พอร์ทัล…") อีเมลฝั่งสมาชิกทั้งหมดจะส่งถึงผู้ติดต่อที่ผูกกับบัญชีที่กดส่งเรื่อง จึงต้องเป็นอีเมลนี้ |
| P4 | แพ็กเกจของสมาชิกทดสอบมีสิทธิ์ E-Blast **อย่างน้อย 3 ครั้ง** | E-Blast ทดสอบแต่ละฉบับจะกันสิทธิ์ไว้หนึ่งครั้ง ตั้งแต่ส่งเรื่องจนกว่าจะส่งจริง ถูกปฏิเสธ ถูกถอน หรือหมดอายุ |
| P5 | E-Blast ทดสอบ **ทุกฉบับ** เลือกผู้รับแบบ **รายชื่อกำหนดเอง** และใส่เฉพาะอีเมลตาม P2/P3 | ผู้รับแบบอื่นจะส่งถึงสมาชิกจริง |
| P6 | ผู้ร่วมทดสอบต้องรวม **ผู้ใช้บทบาทการตลาด (marketing) ทุกคนที่ใช้งานอยู่** ของ SweCham (ถ้าไม่มีเลย ให้รวมผู้ดูแลระบบทุกคนที่ใช้งานอยู่) | อีเมลแจ้งส่งต่องานจะส่งถึงทั้งกลุ่มนี้ ไม่ใช่แค่คนที่กำลังทดสอบ |
| P7 | ตั้งค่า **แบรนด์** แล้ว (`/admin/settings/broadcasts/brand`: สีและที่อยู่ไปรษณีย์) | เพื่อให้การทดสอบได้เห็นโลโก้ส่วนหัว ปุ่มสีแบรนด์ และที่อยู่จริงในส่วนท้ายอีเมล |
| P8 | ปรับปรุง **บันทึกกิจกรรมการประมวลผลข้อมูลส่วนบุคคล (RoPA)** แล้ว | ต้องเสร็จก่อนเปิดสวิตช์ |
| P9 | ผู้ดูแลระบบเปิด `FEATURE_EBLAST_MEMBER_APPROVAL` ใน Vercel แล้ว | การเปิดสวิตช์นี้ **คือการ deploy ระบบจริง — ผู้ดูแลระบบเท่านั้นเป็นผู้ทำ** นับจากนั้นฝ่ายการตลาดจะได้รับอีเมลทุกครั้งที่มีสมาชิกจริงส่ง E-Blast และปุ่ม "เริ่มจัดรูปแบบฉบับใหม่" จะแสดงกับ E-Blast ที่รอตรวจสอบทุกฉบับ |
| P10 | Resend ใช้แพ็กเกจฟรี: **ส่งพร้อมกันได้ไม่เกินสองฉบับ** | ทดสอบทีละฉบับ การจัดรูปแบบและการอนุมัติไม่ใช้โควตา Resend มีเพียงการส่งจริงขั้นสุดท้ายเท่านั้นที่ใช้ |

**บทบาทในเอกสารนี้**: **สมาชิก** = บัญชีพอร์ทัลตาม P3 **ฝ่ายการตลาด** = เจ้าหน้าที่บทบาทการตลาด
**ผู้สังเกตการณ์** = ผู้คอยตรวจกล่องจดหมาย

**เปิดแบบบันทึกผล (หัวข้อ 5) ไว้ตลอดการทดสอบ** ทุกขั้นให้จดสิ่งที่เห็น และกล่องจดหมายใดบ้างที่ได้รับอีเมล

## 2. ชุดทดสอบ A — เส้นทางหลัก (ส่งเรื่อง → ส่งจริง)

ตั้งหัวข้อให้เห็นชัดว่าเป็นการทดสอบ เช่น `[UAT A] งานสังสรรค์เครือข่ายช่วงฤดูใบไม้ผลิ`

### ขั้นที่ 1 — ส่งเรื่อง (สมาชิก)

1. เข้าสู่ระบบในฐานะสมาชิก แล้วเปิดหน้าเขียน E-Blast (`/portal/broadcasts/new`)
2. ใส่หัวข้อและข้อความสั้น ๆ
3. เลือกผู้รับแบบ **รายชื่อกำหนดเอง** และใส่เฉพาะอีเมลตาม P2/P3
4. เลือกเวลาส่งล่วงหน้าประมาณหนึ่งสัปดาห์ แล้วกด **ส่ง**

**ผลที่ควรเห็น**
- รายการ E-Blast ของสมาชิกแสดงสถานะ **รอตรวจสอบ**
- ฝ่ายการตลาดเห็นรายการนี้ที่ `/admin/broadcasts` ในสถานะ **รอตรวจสอบ** และเมนูเจ้าหน้าที่แสดง
  จำนวนงานที่รออยู่
- กล่องจดหมายของฝ่ายการตลาดทุกคน (P6) ได้รับอีเมล "มี E-Blast ใหม่" หนึ่งฉบับ ซึ่งมี **เพียง**
  หัวข้อ ชื่อบริษัทสมาชิก สถานะ และลิงก์ — ไม่มีเนื้อหาข้อความ
- ไม่มีใครอื่นได้รับอีเมล

### ขั้นที่ 2 — จัดรูปแบบ (ฝ่ายการตลาด)

1. เปิด E-Blast จาก `/admin/broadcasts` การ์ด **รอบการอนุมัติ** แสดงผู้ที่ต้องดำเนินการเป็น
   **ฝ่ายการตลาด** และรอบเป็น **ยังไม่ได้ส่งให้สมาชิก**
2. กด **เริ่มจัดรูปแบบฉบับใหม่** แล้วกดยืนยัน **เริ่มจัดรูปแบบฉบับใหม่** ในหน้าต่างยืนยัน (ระบบจะเตือน
   ว่าจะไม่สามารถอนุมัติแบบตามที่ส่งมาได้อีก)

**ผลที่ควรเห็น**: สถานะเป็น **กำลังออกแบบ** ต้นฉบับของสมาชิกแสดงอยู่ข้างฉบับที่กำลังแก้ไข
โดยอ่านได้อย่างเดียวและไม่ถูกเปลี่ยนแปลง

3. จัดรูปแบบฉบับที่กำลังแก้ไข: เพิ่ม **หัวข้อระดับ H2** **ภาพแบนเนอร์** (พร้อมคำบรรยายภาพ) และ
   **ปุ่มเชิญชวน (call-to-action)** แล้วเขียน **หมายเหตุถึงสมาชิก** สั้น ๆ
4. กด **บันทึก**

**ผลที่ควรเห็น**: มีข้อความ "บันทึกเมื่อ HH:MM"

5. (ไม่บังคับ) กด **ส่งฉบับทดสอบให้ฉัน**

**ผลที่ควรเห็น**: อีเมลส่งถึง **อีเมลของคุณเองเท่านั้น** หัวข้อขึ้นต้นด้วย `[Test]` และสถานะไม่เปลี่ยน

### ขั้นที่ 3 — ส่งให้สมาชิกพิจารณา (ฝ่ายการตลาด)

1. กด **ส่งให้สมาชิก** แล้วยืนยัน **ส่งให้สมาชิก** (ระบบจะบันทึกการแก้ไขที่ค้างอยู่ให้ก่อน)

**ผลที่ควรเห็น**
- สถานะเป็น **รอสมาชิกอนุมัติ** รอบที่ **1** ผู้ที่ต้องดำเนินการคือ **สมาชิก**
- ฉบับนี้แก้ไขไม่ได้อีกแล้ว
- อีเมลของสมาชิก (P3) ได้รับอีเมล "มีฉบับใหม่รอคุณอนุมัติ" หนึ่งฉบับ **เป็นภาษาที่ผู้ติดต่อของสมาชิก
  เลือกไว้** และระบุกำหนดเวลาไว้ชัดเจน คือ เตือนครั้งแรกวันที่ 3 เตือนครั้งสุดท้ายวันที่ 7 แจ้งเตือน
  ล่วงหน้าวันที่ 23 และปิดเรื่องอัตโนมัติวันที่ 30
- ไม่มีใครอื่นได้รับอีเมล

### ขั้นที่ 4 — สมาชิกขอแก้ไข (สมาชิก)

1. เข้าสู่ระบบในฐานะสมาชิก แล้วเปิด E-Blast จากรายการ (สถานะตอนนี้คือ **รอการอนุมัติจากคุณ**)

**ผลที่ควรเห็น**: แถบแจ้งว่าถึงคราวคุณต้องตัดสินใจ พร้อมวันที่ต้องตอบกลับ ฉบับที่หอการค้า
จัดรูปแบบแสดง **ก่อน** และต้นฉบับอยู่ข้าง ๆ (บนมือถือจะอยู่ด้านล่างในหน้าเดียวกัน) มีหมายเหตุจาก
หอการค้า และเวลาส่งที่เสนอกับเวลาส่งที่ยืนยันแล้ว (ช่องเวลาที่เสนอคือเวลาที่เลือกไว้ในขั้นที่ 1 ส่วน
ช่องเวลาที่ยืนยันขึ้นว่า "ยังไม่ได้กำหนด" เพราะฝ่ายการตลาดยังไม่ได้ยืนยัน)

2. กด **ขอให้แก้ไข** โดยไม่กรอกเหตุผล แล้วกดยืนยัน

**ผลที่ควรเห็น**: ระบบไม่ยอมรับ และขึ้นว่า "โปรดแจ้งหอการค้าว่าควรแก้ไขอะไร"

3. กรอกเหตุผล (เช่น "ช่วยย้ายวันที่ขึ้นไปไว้ในหัวข้อ") แล้วกดยืนยัน **ขอให้แก้ไข**

**ผลที่ควรเห็น**
- ฝั่งสมาชิก: สถานะเป็น **ขอให้แก้ไขแล้ว**
- ฝ่ายการตลาดได้รับอีเมลที่มีหัวข้อ ชื่อบริษัท สถานะใหม่ และลิงก์ — **ไม่มีเหตุผลที่สมาชิกเขียน**
- ในหน้าของเจ้าหน้าที่ เหตุผลแสดงอยู่ พร้อมระบุว่าเป็นของรอบที่ 1

### ขั้นที่ 5 — จัดรูปแบบใหม่ (ฝ่ายการตลาด)

1. เปิด E-Blast แล้วกด **เริ่มจัดรูปแบบฉบับใหม่** (เป็นการเริ่มรอบที่ 2)
2. แก้ตามที่สมาชิกขอ กด **บันทึก** แล้วกด **ส่งให้สมาชิก**

**ผลที่ควรเห็น**
- รอบที่ **2** สถานะ **รอสมาชิกอนุมัติ**
- สมาชิกได้รับอีเมล "มีฉบับใหม่รอคุณอนุมัติ" อีกฉบับ
- ประวัติทั้งสองฝั่งแสดงรอบที่ 1 (ฉบับที่ส่งและคำขอแก้ไข) และรอบที่ 2 เรียงจากเก่าไปใหม่

### ขั้นที่ 6 — สมาชิกอนุมัติ (สมาชิก)

1. ในฐานะสมาชิก เปิด E-Blast แล้วกด **อนุมัติ**

**ผลที่ควรเห็น**: หน้าต่างยืนยันแจ้งว่าฝ่ายการตลาดของหอการค้าจะยืนยันเวลาส่งต่อจากนี้ และเนื้อหา
จะเปลี่ยนไม่ได้หากไม่ได้รับการอนุมัติใหม่ ช่องหมายเหตุไม่บังคับ (ไม่เกิน 500 ตัวอักษร)

2. กดยืนยัน **อนุมัติ**

**ผลที่ควรเห็น**
- ฝั่งสมาชิก: **อนุมัติแล้ว — รอกำหนดส่ง** ฝั่งเจ้าหน้าที่: **สมาชิกอนุมัติแล้ว — รอกำหนดส่ง**
- ฝ่ายการตลาดได้รับอีเมล (หัวข้อ บริษัท สถานะ ลิงก์)

### ขั้นที่ 7 — ยืนยันเวลาส่ง (ฝ่ายการตลาด)

1. เปิด E-Blast แล้วกด **ยืนยันกำหนดเวลาส่ง**

**ผลที่ควรเห็น**: หน้าต่างแสดง "เวลาที่สมาชิกเสนอ: …" เป็นเวลาที่เลือกไว้ในขั้นที่ 1 และมีตัวเลือก
**ใช้เวลาที่สมาชิกเสนอ** อยู่ในตัวเลือกการส่ง

2. เลือก **เลือกเวลาอื่น** ตั้งเวลา **ล่วงหน้าอย่างน้อย 5 นาที** (เวลากรุงเทพฯ) — เพื่อไม่ต้องรอ
   เวลาที่เสนอไว้อีกหนึ่งสัปดาห์ — แล้วกด **ยืนยัน**

**ผลที่ควรเห็น**: ก่อนกดยืนยัน หน้าต่างจะเตือนว่า "เวลานี้ไม่ใช่เวลาที่สมาชิกเสนอ (…) ระบบจะแจ้งการเปลี่ยนแปลงให้สมาชิกทราบ"

**ผลที่ควรเห็น**
- สถานะเป็น **กำหนดส่งแล้ว**
- สมาชิกได้รับอีเมลแจ้งเวลาส่งที่ยืนยันแล้ว พร้อมเวลาที่เสนอไว้ และบรรทัด "เวลานี้ไม่ใช่เวลาที่คุณเสนอไว้"
- (สำหรับผู้ดูแลระบบ ตรวจเพิ่มเติมได้) ข้อมูลที่จะส่งจริงต้องตรงกับฉบับที่อนุมัติทุกตัวอักษร:
  `SELECT b.subject = v.subject AND b.body_html = v.body_html FROM broadcasts b JOIN broadcast_versions v ON v.tenant_id = b.tenant_id AND v.id = b.approved_version_id WHERE b.broadcast_id = '<id>';`
  ต้องได้ผลเป็น `true`

### ขั้นที่ 8 — ส่งจริง (ระบบทำเอง)

รอจนถึงเวลาที่ยืนยันไว้ และเผื่ออีกไม่เกิน 5 นาที (ระบบตรวจงานที่ถึงเวลาส่งทุก 5 นาที)

**ผลที่ควรเห็น**
- สถานะเปลี่ยนเป็น **กำลังส่ง** แล้วเป็น **ส่งแล้ว**
- **เฉพาะ** อีเมลตาม P2/P3 เท่านั้นที่ได้รับ E-Blast และเป็นฉบับรอบที่ 2 ที่สมาชิกอนุมัติ ครบทั้งหัวข้อ
  แบนเนอร์ ปุ่ม โลโก้ (หรือชื่อหอการค้า) และส่วนท้ายที่มีที่อยู่ไปรษณีย์กับลิงก์ยกเลิกรับข่าวสาร
- หน้าของเจ้าหน้าที่แสดงจำนวนผู้รับ ส่งสำเร็จ ตีกลับ และร้องเรียน ส่วนหน้าของสมาชิกแสดงการ์ด
  **สรุปผลการจัดส่ง** ซึ่งจะปรากฏเมื่อเริ่มส่งแล้วเท่านั้น
- **ตลอดทุกขั้น ไม่มีใครนอกรายชื่อได้รับอีเมลเลย** นี่คือเกณฑ์ผ่านของ SC-005

## 3. ชุดทดสอบ B — สถานะที่เหลือ

ใช้ E-Blast ทดสอบฉบับ **ใหม่** (`[UAT B1]`, `[UAT B2]` …) ทีละฉบับ และใช้สิ่งที่เตรียมไว้ชุดเดิม
ฉบับที่จบโดยไม่ได้ส่งจริงจะคืนสิทธิ์ E-Blast ให้สมาชิก

| ข้อ | สิ่งที่ทำ | สถานะที่ได้ทดสอบ | ผลที่ควรเห็น |
|---|---|---|---|
| B1 | ส่งเรื่อง แล้วฝ่ายการตลาดกด **อนุมัติและนัดส่ง** ตามที่ส่งมา ตั้งเวลาล่วงหน้าไม่กี่นาที | ขั้นตอนแบบเดิม → กำหนดส่งแล้ว → ส่งแล้ว | ไม่มีรอบให้สมาชิกพิจารณา ประวัติทั้งสองฝั่งมีรายการเดียวว่า "อนุมัติตามที่ส่งมา" พร้อมชื่อเจ้าหน้าที่และเวลา |
| B2 | ส่งเรื่อง ฝ่ายการตลาดเริ่มจัดรูปแบบ แล้วกด **ปฏิเสธ** พร้อมเหตุผล | กำลังออกแบบ → ปฏิเสธ | สมาชิกได้รับแจ้งพร้อมเหตุผล และได้สิทธิ์คืน |
| B3 | ทำตามชุด A ขั้น 1–7 จนถึง **กำหนดส่งแล้ว** จากนั้นสมาชิกกด **ถอนการอนุมัติ** พร้อมเหตุผลก่อนถึงเวลาส่ง | กำหนดส่งแล้ว → ขอให้แก้ไขแล้ว | เวลาส่งที่ยืนยันถูกยกเลิก E-Blast **ไม่ถูกส่ง** ฝ่ายการตลาดได้รับอีเมล ประวัติแสดงการถอนพร้อมเหตุผล และเลขรอบ **ไม่เปลี่ยน** |
| B4 | ระหว่างที่รอสมาชิกอนุมัติ ให้ฝ่ายการตลาดกด **ปฏิเสธ** หรือให้สมาชิกกด **ยกเลิก E-Blast** จากหน้ารายละเอียด | รอสมาชิกอนุมัติ → ปฏิเสธ / ยกเลิก | อีกฝ่ายได้รับแจ้ง และได้สิทธิ์คืน |
| B5 | ระหว่างที่มีฉบับรอสมาชิกอนุมัติ ให้เปลี่ยนสีแบรนด์ | ทุกสถานะ | ไม่มีการอนุมัติใดถูกยกเลิก และตัวอย่างครั้งถัดไปกับการส่งจริงใช้สีใหม่ |
| B6 | เข้าสู่ระบบด้วยบทบาท **ผู้จัดการ (manager)** แล้วเปิด `/admin/broadcasts` และ E-Blast หนึ่งฉบับ | อ่านอย่างเดียว | เห็นข้อมูลครบ แต่ไม่มีปุ่มดำเนินการใด ๆ |

**สถานะที่ทดสอบในระบบจริงภายในวันเดียวไม่ได้**: การเตือนวันที่ 3 และวันที่ 7 การแจ้งเตือนล่วงหน้า
วันที่ 23 และการปิดเรื่องเป็น **หมดอายุ — สมาชิกไม่ตอบกลับ** ในวันที่ 30 ทำงานตามวันจริงบนปฏิทิน
ผู้ดูแลระบบจะสาธิตให้ดูในระบบ **dev** โดยย้อนเวลาของข้อมูลทดสอบ (`quickstart.md` หัวข้อ 1, US5
ขั้นที่ 2) แล้วแชร์อีเมลที่ได้ให้ทีมดู ห้ามย้อนเวลาข้อมูลในระบบจริงเด็ดขาด

## 4. ถ้ามีปัญหา

- **ส่งเรื่องไม่ผ่าน และมีข้อความเกี่ยวกับรายชื่อผู้รับ** → ยังไม่ได้ทำ P2 คือมีอีเมลในรายชื่อที่ยังไม่ได้
  เป็นผู้ติดต่อของสมาชิกทดสอบ
- **ขึ้นว่า "บริษัทสมาชิกยังไม่มีผู้ใช้พอร์ทัล"** ตอนกดส่งให้สมาชิก → ยังไม่ได้ทำ P3
- **มีอีเมลไปถึงคนที่ไม่ควรได้รับ** → หยุดทันที ยกเลิก E-Blast จากหน้าของเจ้าหน้าที่ (กด **ยกเลิก
  E-Blast** พิมพ์ข้อความยืนยัน และใส่เหตุผล) จดชื่อผู้รับและเวลาไว้ แล้วแจ้งผู้ดูแลระบบ ถือว่า
  SC-005 ไม่ผ่าน
- **ไม่มีอีเมลมาถึง** → แจ้งผู้ดูแลระบบ เพื่อตรวจคิวอีเมล (runbook `docs/runbooks/eblast-approval.md`
  หัวข้อ Triage)
- **ต้องการหยุดการทดสอบทั้งหมด** → ยกเลิก E-Blast ทดสอบที่ยังค้างอยู่ การปิดสวิตช์เป็นการตัดสินใจ
  ของผู้ดูแลระบบ และเป็นการ deploy ระบบจริงในตัว E-Blast ที่อยู่ในขั้นตอนใหม่แล้วจะยังดำเนินต่อ
  หรือยกเลิกได้หลังปิดสวิตช์
