# Data Model: AURA Design-System Migration

**No persistent data changes.** This is a presentation-layer feature: no tables, columns, migrations, enums, audit events or API payloads are added or changed (FR-011).

The only "entities" are design-time artefacts:

| Entity | Where it lives | Rules |
|---|---|---|
| **Design token** | `@jirawatpyk/aura-tokens/aura.css` (`--aura-*`), plus the brand theme `src/styles/aura-theme.css` | Owned by AURA. Chamber-OS never edits token values, only the generated brand theme. Legacy shadcn vars are aliases (see `contracts/css-layers.md`). |
| **Brand theme** | `src/styles/aura-theme.css` | Generated by `aura-theme --brand "#10487A"`. The CLI must exit 0, meaning every contrast check passes. Committed and regenerated only by the CLI. F12 may later make it per-tenant at runtime. |
| **Migrated path** | `MIGRATED_PATHS` in `eslint.config.mjs` | Append-only per phase. A path is listed only when it has zero `@/components/ui` imports. Deleted at US13. |
| **AURA handoff item** | AURA handoff doc (Claude Doc), items 1–53 | Each has a Gap, a Proposed, an Accept-when and a Chamber-OS-meanwhile. A local wrapper bridging an open item carries a `// AURA-handoff #NN` comment and is removed when the item ships. |
| **Canvas board** | the "Chamber-OS Portal — Aura" design canvas | The visual acceptance reference per screen state and width. Boards marked "Proposed" may be implemented or deferred, and the PR says which. |
